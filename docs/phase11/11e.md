1. **`Settings`** : lecture d'une chaîne sans `[ERROR]` quand la clé est absente
   (`getString` écrit `Tried to use unset setting`, `Settings.cpp:138`). Ajoute par exemple
   `std::string getStringOr(const std::string& name, const std::string& fallback)`, avec test.
   Ne change pas `getString`.

   premier jeu quand il n'existe pas, comme `GuiMenu` et `getThemeFromCurrentSet`). Le
   chargeur et le menu l'utilisent tous les deux : pas de deuxième règle.
3. **Chargement** (`ThemeData::loadFile`) : `ctx.region` = `getStringOr("ThemeRegion", "eu")`
   (valeur hors de `us`/`eu`/`jp` : avertissement, `eu`) ; `ctx.selectedOptions` = pour chaque
   option, `getStringOr(optionSettingKey(jeu, subset), "")` si non vide. Le reste du
   chargement ne change pas. `--check-theme` ne lit aucun réglage (comportement actuel).
4. **`ThemeData`** expose ce que le menu affiche : les options du thème chargé (identifiant,
   titre et aide localisés, valeurs et leur nom affiché, valeur utilisée) et un booléen « le
   thème utilise l'attribut `region` » (le chargeur le relève, une ligne suffit). Données
   prises au chargement, pas de seconde lecture des fichiers.
5. **Menu** « UI settings » (`GuiMenu.cpp`), juste après « Theme set » :

     option ; ouvre un `GuiSettings` avec une liste par option (titre = titre du thème,
     valeurs triées comme Recalbox) ;
   - « Theme region » (`_()`, valeurs `us`/`eu`/`jp`) **seulement** si ce thème utilise
     `region` ;
   - à la fermeture : `setString` des valeurs **changées** seulement, `saveFile`,
     `ViewController::reloadAll()` une fois, comme pour « Theme set » ;
   - thème sans option ni `region` (thème de capture format 3) : menu **identique** à
     aujourd'hui, `06-ui-settings` de `capture.sh` à 0 pixel (R5).
6. **Traductions** : seuls les nouveaux libellés du menu passent par `_()` ; les textes venant du
