## Conception imposée

- `es-core/src/MenuTheme.h` : chaque valeur est un `std::optional` (absente = le composant
  garde sa valeur actuelle, en 11f2). Par exemple :
  ```cpp
  struct MenuFont { std::string path; float size; };   // size en fraction de la hauteur d'écran
  struct MenuTextStyle {
      std::optional<MenuFont> font;
      std::optional<unsigned int> color, selectedColor, selectorColor, separatorColor;
  };
  struct MenuTheme {
      std::optional<float> height;
      std::optional<std::string> backgroundPath, fadePath;
      std::optional<unsigned int> backgroundColor;
      MenuTextStyle title, footer, text, textSmall, section;
      std::optional<Alignment> sectionAlignment;            // enum existant (ALIGN_LEFT…, TextComponent)
      std::optional<std::string> buttonPath, buttonFilledPath, switchOnPath, switchOffPath, sliderKnobPath;
      std::map<MenuIcon, std::string> icons;              // enum MenuIcon : un par propriété icon…
      static MenuTheme fromTheme(const ThemeData& theme);  // vue "menu", règles ci-dessus
  };
  struct KeyboardTheme {                                   // 8 couleurs et fontPath, tous optionnels
      std::optional<unsigned int> keyColor /* , … */;
      std::optional<std::string> fontPath;
      static KeyboardTheme fromTheme(const ThemeData& theme, const std::string& view);
  };
  ```
  Aucune valeur par défaut d'ES dans cette structure : elles restent dans les composants
  (11f2). Pas de `Renderer`, pas de `Font`, pas de `Window` dans `MenuTheme` : la structure se
  teste sans fenêtre.
- **Chargement du thème principal** : une fonction de `ThemeData` (par exemple
  `static std::shared_ptr<ThemeData> loadMainTheme()`) charge `<jeu>/theme.xml` du jeu courant
  (`currentThemeSetName()` de 11e2) avec `ThemeSystemInfo{}` ; fichier absent → `nullptr` sans
  `[ERROR]` ; `ThemeException` → journal `[WARNING]`, `nullptr`. Les réglages d'options et de
  région s'appliquent comme pour un système (11e2).
- **Accès** : `Window` garde le thème principal (`std::shared_ptr<const ThemeData>`, pour le
  clavier qui lit la vue au moment de s'ouvrir) et le `MenuTheme` qui en est tiré
  (`const MenuTheme& getMenuTheme() const`, `void setMainTheme(std::shared_ptr<const ThemeData>)`
  qui remplit les deux). Il est rempli au démarrage avant la première vue
  (`es-app/src/main.cpp`) et dans `ViewController::reloadAll()`. Pas de singleton nouveau.
- `--check-theme <jeu> ""` vérifie déjà le thème principal (`getThemePath("")` donne
  `<jeu>/theme.xml`) : écris-le dans `THEMES.md` section 13, aucune option nouvelle.

## Tests (chaque `TEST_CASE` ajouté porte l'étiquette `[11f1]`)

Fixture `tests/data/themes/menu/` : un `theme.xml` format 4 **original** (pas de copie d'un thème
Recalbox) avec une vue `menu` qui utilise chaque élément et chaque propriété du tableau, des
fichiers d'image vides présents pour les chemins, et un second fichier sans vue `menu`.

- Thème sans vue `menu` → toutes les valeurs de `MenuTheme` vides (`!has_value()`), une
  vérification par champ.
- Chaque propriété du tableau lue dans le bon champ (une vérification par propriété).
- Police : `fontPath` seul → taille par défaut de l'élément (une vérification par élément) ;
  `fontSize` seul → police par défaut.
- Héritage : `menutext` avec couleur et police, sans `menutextsmall` → `textSmall` identique à
  `text` ; avec `menutextsmall` qui donne sa couleur → seule la couleur change.
- Particularité `:72-73` : `menutextsmall` avec `selectorColor` → `text.selectedColor` changé,
  `textSmall.selectorColor` inchangé.
- `menusection` : sans élément → copie de `text` ; avec couleur seule → seule la couleur
  change ; `alignment` `left`, `right`, `center`, `xyz` → gauche, droite, centré, centré ; police
  avec `fontSize` seul → chemin de la police de `text`.
- `menuicons` : chacune des 23 propriétés remplit la bonne entrée de `icons` (un test qui
  parcourt la liste), `iconList` compris ; sans élément → `icons` vide.
- `KeyboardTheme::fromTheme` : élément `keyboard` dans `system` et dans `menu` avec des couleurs
  différentes → chaque vue rend les siennes ; vue sans élément → tout vide ; chacune des 9
  propriétés lue.
- Élément au bon nom mais d'un autre type (`<text name="menutitle">`) → ignoré.
- `loadMainTheme()` : `<jeu>/theme.xml` présent → thème chargé sans système (`${system.name}`
  vide : un include qui en dépend est sauté) ; absent → `nullptr`, aucune ligne `[ERROR]`.
- `Window` : `setMainTheme` puis `getMenuTheme` rend les valeurs du thème donné ; sans appel
  ou avec `nullptr`, valeurs vides.
