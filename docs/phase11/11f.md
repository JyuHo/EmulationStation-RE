## Objectif

**Menus thémés** : appliquer la vue `menu` du thème (éléments listés par `docs/THEMES.md` :
fond, textes de titre / d'entrée / de pied / petit texte, couleurs de sélection et de
séparateur, interrupteurs, curseurs, boutons, icônes de menu, système d'aide des menus) aux
fenêtres de menus d'ES.

## Conception

- Une structure `MenuTheme` (es-core) remplie depuis la vue `menu` du thème courant, avec les
  **valeurs actuelles d'ES comme défauts** : un thème sans vue `menu` donne exactement le rendu
  d'aujourd'hui (R5, écrans 05 à 08).
- Les composants de menu (`MenuComponent`, `ComponentList`, `SwitchComponent`,
  `SliderComponent`, `ButtonComponent`, `OptionListComponent`, `HelpComponent`…) lisent
  `MenuTheme` au lieu de leurs constantes en dur. Inventaire exhaustif des constantes de couleur,
  police et image des menus dans la PR (R2).
- `delete this` (reliquat de 3.D, `PROMPT.md` 0.2) : pour chaque GUI que tu touches, remplace la
  fermeture par une méthode de `Window` qui ferme une GUI possédée ; si tu changes
  `Window::removeGui`, traite **toutes** les GUI concernées dans cette PR et étends
  `test_Window.cpp` (piège 0.3, double libération de #6). Sinon ne touche pas à ce mécanisme.
- Écran de `GamepadSwapAB` (0.2) : seulement si `docs/THEMES.md` ou le propriétaire l'a
  confirmé ; sinon hors périmètre, à noter dans « Suite prévue ».

## Tests

- `MenuTheme` : défauts identiques aux constantes actuelles (un test par valeur), lecture d'une
  vue `menu` de fixture, propriété invalide → défaut + avertissement.
- `capture-themes.sh` : un menu ouvert avec un thème qui change fond, couleur de texte, couleur
  de sélection et image d'interrupteur ; sondes sur chacun.
